# Пошаговый план разработки TerminalControl для Avalonia

## Этап 0. Подготовка
- Создать новый проект `Avalonia UI` (можно `Avalonia Application`).
- Добавить класс `TerminalControl`, унаследованный от `TemplatedControl`.
- В теме (Theme) определить стандартный визуальный шаблон: например, `ScrollViewer` + `ItemsControl` (для строк) или кастомный рендерер через `DrawingContext`.

## Этап 1. Простейший вывод текста (без ANSI)
**Цель:** отображать построчно текст, который приходит через метод `WriteLine()`.

- Добавить свойство `ObservableCollection<string> Lines`.
- В `WriteLine` добавить строку в коллекцию.
- Использовать `ItemsControl`, привязанный к `Lines`, с `VirtualizingStackPanel`.
- Добавить `ScrollViewer` и автоматическую прокрутку вниз.

✅ **Проверка:** вызываем `Terminal.WriteLine("Hello")` – видим строку.

## Этап 2. Буфер и ограничение истории
- Заменить `ObservableCollection` на собственную кольцевую очередь (или список с автообрезкой).
- Добавить свойство `MaxHistoryLines`.
- При добавлении строки проверять лимит и удалять старые.

## Этап 3. Поддержка простейшего ввода
- Добавить обработку клавиш в `OnKeyDown`.
- Собирать введённые символы в буфер текущей строки.
- По `Enter` генерировать событие `InputReceived` и очищать буфер.
- Отображать текущую строку ввода (например, отдельным элементом внизу, но лучше прямо на последней строке с курсором).

✅ **Проверка:** можно ввести текст, нажать Enter – событие сработало.

## Этап 4. Курсор и перемещение по строке
- Отслеживать позицию курсора внутри текущей строки.
- Обрабатывать стрелки Влево/Вправо, Home, End.
- Отображать курсор (мигающий блок) – можно через `Timer` или анимацию в Avalonia.

## Этап 5. Минимальный ANSI-парсер (цвет и перемещение курсора)
- Разобрать несколько простых последовательностей: `\x1b[31m` (красный), `\x1b[0m` (сброс), `\x1b[1;32m` (жирный зелёный).
- Хранить не просто строки, а массив **ячеек** (`Cell`) с полями `Char`, `Foreground`, `Background`, `Bold` и т.д.
- При выводе обновлять состояние курсора (позиция X,Y) и применять текущие атрибуты к вставляемым символам.

✅ **Проверка:** `Terminal.Write("\x1b[31mRed Text\x1b[0m")` – отображается красным.

## Этап 6. Полноценный эмулятор буфера (позиционирование, очистка, вставка/удаление)
- Реализовать двумерный массив ячеек (размер `Rows x Cols`), плюс история для прокрутки.
- Поддержка перемещения курсора `\x1b[<row>;<col>H`, очистки экрана `\x1b[2J`, удаления строки `\x1b[K` и т.д.
- Это самый трудоёмкий этап. Можно взять готовый легковесный эмулятор (например, [Terminal emulator in C#](https://github.com/migueldeicaza/guietta/tree/master/Terminal)) и адаптировать под Avalonia.

## Этап 7. Поддержка палитр (256 цветов, True Color)
- Расширить структуру `Cell` для хранения 24-битного цвета.
- Парсер должен понимать `\x1b[38;2;R;G;Bm` и `\x1b[38;5;Nm`.

## Этап 8. Виртуализация и производительность
- Перейти с `ItemsControl` на кастомный рендер, который рисует только видимые строки/ячейки через `DrawingContext`.
- Использовать `ScrollViewer` + `Canvas` или выделенный контрол с переопределённым `OnRender`.

## Этап 9. Скроллинг история + альтернативный буфер
- Добавить поддержку `\x1b[?1049h` (альтернативный буфер) – отдельный двумерный массив.
- При переключении буфера сохранять/восстанавливать основной.

## Этап 10. Буфер обмена, выделение мышью
- Обработка `PointerPressed` / `PointerMoved` для выделения.
- Копирование по `Ctrl+C` / `Ctrl+Insert`.
- Вставка по `Ctrl+V`.

## Этап 11. Интеграция с реальным процессом (PTY)
- Добавить класс `PtyProcess` (через `Pty.Net` для Unix и `ConPTY` для Windows).
- Связать потоки с терминалом: `process.Output` → `Terminal.Write`, `Terminal.InputReceived` → `process.StandardInput`.

## Этап 12. Стилизация, темы, настройки
- Вынести цвета в `ResourceDictionary` с поддержкой динамической смены.
- Добавить свойства для шрифта, размера, формы курсора.

## Этап 13. Документация, примеры, NuGet-пакет
- Написать `README.md`, пример использования, XML-комментарии.
- Упаковать в `.nupkg`.

---

**Рекомендация:** ведите разработку итеративно, после каждого этапа проверяйте работоспособность. 
Не пытайтесь реализовать всё сразу — лучше иметь минимально работающий терминал на ранних этапах и постепенно наращивать функциональность.
